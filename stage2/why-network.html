왜 개발자가 네트워크를 공부해야 하나

요청 하나가 브라우저에서 DB까지 지나가는 길과, 그 길 위에서 생기는 장애 · 성능 · 보안 문제 · STAGE 2 네트워크 · 2026-11-23

  • 이유 다섯 가지
  • 어디까지 알아야 하나

한 줄 답

  • 요즘 프로그램은 거의 다 여러 컴퓨터가 주고받으며 동작한다. 그 주고받는 길이 네트워크다.
  • 그래서 장애 · 성능 · 보안 문제의 상당수가 코드 밖, 길 위에서 생긴다. 길을 모르면 원인을 찾지 못하고 "서버가 이상해요"에서 멈춘다.
  • 개발자에게 필요한 건 장비 설정 능력이 아니라 "어디서 막혔는지" 가설을 세우고 확인하는 능력이다.

1. 요청 하나가 지나가는 길

웹 페이지 하나를 여는 동안 요청은 최소 여섯 구간을 지난다. 코드(맨 아래 WAS)는 그중 한 구간일 뿐이다. 어느 구간에서 막혔는지에 따라 에러 메시지가 다르게 나온다.

에러 메시지무슨 뜻인가먼저 볼 곳
Name or service not known도메인을 IP로 못 바꿈DNS 설정 · /etc/hosts · dig
Connection timed out요청이 갔는데 아무 대답이 없음 — 중간에서 조용히 버려짐방화벽 · 공유기 포트포워딩 · 라우팅
Connection refused서버까지는 갔는데 그 포트에서 기다리는 프로그램이 없음서비스 기동 여부 · ss -tlnp · 바인드 주소
403 / 502 / 504연결은 됐고, 웹서버 · WAS 단계에서 문제웹서버 로그 · WAS 상태 · 타임아웃 설정

에러 메시지만 정확히 읽어도 원인 범위가 절반으로 줄어든다. timed out과 refused는 완전히 다른 곳을 가리킨다.

2. 개발자가 네트워크를 알아야 하는 이유 다섯 가지

1.장애의 절반은 코드 밖에서 난다

고객사에서 "STT 웹이 안 열려요"라는 전화가 오면, 원인은 PHP 코드보다 방화벽 · 포트 · DNS · 서비스 미기동인 경우가 훨씬 많다. 위 표처럼 에러를 계층별로 나눠 읽을 수 있어야 엉뚱한 곳을 뒤지지 않는다.

2.성능은 왕복 횟수가 결정한다

네트워크 요청 한 번은 메모리 접근보다 수만~수백만 배 느리다(STAGE 1 메모리 계층의 연장선). 같은 서버실 안에서도 왕복 한 번에 약 0.5ms, 서울–부산은 수 ms가 걸린다.

  • DB 쿼리를 루프 안에서 100번 부르면 쿼리 자체보다 왕복 100번이 느리다 → 한 번에 가져오기
  • 요청마다 TCP 연결을 새로 맺으면 그때마다 왕복이 늘어난다 → 연결 재사용(keep-alive · 커넥션 풀)

3.보안 사고는 네트워크로 들어온다

11/21 홈서버에 SSH 무차별 대입 시도가 7,016건 들어왔다. 포트를 바꿔도 막을 수 없었다. 어떤 포트를 누구에게 열지, DB를 왜 127.0.0.1에만 묶는지는 네트워크를 알아야 판단할 수 있다.

4.고객사와 일하려면 네트워크 언어를 써야 한다

금융권 · 공공기관 고객사에 설치하려면 방화벽 오픈 신청서를 써야 한다: 출발지 IP · 목적지 IP · 포트 · 프로토콜(TCP/UDP) · 방향. 이걸 정확히 못 쓰면 설치 날 아무것도 안 된다. 망분리 환경이면 외부 저장소(dnf · npm)도 못 쓴다.

5.STT · 녹취 업무 자체가 네트워크다

통화 음성은 RTP 패킷으로 흐르고, 녹취는 그 패킷을 복사(미러링)하거나 교환기에서 받아(SIP 연동) 만든다. 채널 수만큼 대역폭도 계산해야 한다 — G.711 통화 1채널은 헤더까지 약 87kbps, 100채널이면 약 8.7Mbps.

3. 개발자는 어디까지 알아야 하나

  • 알아야 할 것: 계층 구조(누가 어떤 정보를 붙이는지), IP · 포트 · DNS · TCP 연결, HTTP, NAT와 방화벽이 패킷을 어떻게 다루는지
  • 도구로 확인할 수 있어야 할 것: ping(닿는가) · traceroute(어디까지 가는가) · ss -tlnp(누가 기다리는가) · curl -v(HTTP가 어떻게 오가는가) · nc -zv 호스트 포트(포트가 열렸나) · tcpdump(실제 패킷)
  • 몰라도 되는 것: 라우터 · 스위치의 장비별 설정 명령어, 케이블 규격의 세부 숫자 — 네트워크 엔지니어의 영역

핵심 정리

  • 요청은 브라우저 → DNS → 방화벽 → 인터넷 → 웹서버 → WAS · DB를 지나고, 막힌 구간마다 에러가 다르다
  • timed out = 중간에서 버려짐, refused = 도착했지만 받는 프로그램이 없음
  • 성능은 왕복 횟수, 보안은 열린 포트, 고객사 협업은 방화벽 신청서 — 모두 네트워크 언어
