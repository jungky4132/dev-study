1. 패킷이란

패킷은 보낼 데이터를 작게 쪼갠 조각 + 이름표(헤더)다. 헤더에는 어디서 와서 어디로 가는지, 몇 번째 조각인지가 적혀 있고, 중간 장비는 헤더만 보고 다음 장비로 넘긴다. 내용(페이로드)은 열어보지 않는다.

  • 왜 쪼개나: 큰 데이터 하나가 길을 오래 붙잡지 않게(여럿이 나눠 쓰기), 일부가 깨지면 그 조각만 다시 보내게, 길이 끊기면 조각마다 다른 길로 우회하게
  • 대가: 조각마다 헤더가 붙으니 낭비가 생기고, 순서가 뒤섞이거나 일부가 사라질 수 있다 → 그걸 처리하는 게 TCP의 일
1965 · 이름의 유래 영국 국립물리연구소의 도널드 데이비스가 데이터 조각을 "작은 소포"라는 뜻의 packet으로 불렀다. 여러 언어로 번역하기 쉬운 짧은 단어를 일부러 골랐다고 한다.

2. 패킷의 구조: 계층마다 헤더가 한 겹씩 (캡슐화)

헤더주요 내용누가 읽나
이더넷목적지 MAC · 출발지 MAC · 타입스위치 (같은 LAN 안 다음 장비까지)
IP출발지 IP · 목적지 IP · TTL(최대 몇 번 거칠지) · 프로토콜(TCP/UDP)라우터 (네트워크 사이 길 찾기)
TCP · UDP출발지 포트 · 목적지 포트 (TCP는 순서 번호 · 확인 응답 추가)받는 컴퓨터의 OS (어느 프로그램에게)

이더넷 헤더는 라우터를 지날 때마다 새로 붙고(구간마다 MAC이 바뀜), IP 헤더는 출발부터 도착까지 그대로 간다(NAT를 지나면 주소가 바뀐다). 엄밀히는 계층마다 부르는 이름이 다르지만(세그먼트 · 패킷 · 프레임) 일상에서는 모두 "패킷"이라고 부른다.

3. 패킷은 어떻게 볼 수 있나

① 리눅스: tcpdump

# 홈서버에서: 22번 포트(SSH) 패킷 5개만 보기
sudo tcpdump -i enp3s0 -nn port 22 -c 5

10:53:01.123456 IP 192.168.0.7.51544 > 192.168.0.10.22: Flags [P.], seq 1:37, ack 1, length 36
#   시각           출발지 IP.포트        목적지 IP.포트   TCP 플래그       순서 번호       데이터 36바이트

# 파일로 저장해서 Wireshark로 열기
sudo tcpdump -i enp3s0 -nn -w /tmp/cap.pcap port 80

② PC: Wireshark

  • 필터 예: tcp.port == 22 · ip.addr == 192.168.0.10 · dns · sip || rtp
  • 음성: Telephony → VoIP Calls에서 통화를 고르면 SIP 흐름과 RTP를 보여 주고, RTP Player로 소리를 재생할 수 있다 — 녹취 트랙 S2 실습
  • 주의: 패킷 캡처는 남의 통신 내용을 볼 수 있으므로 내 장비 · 권한 있는 고객사 환경에서만 한다
실습 홈서버에서 tcpdump -nn port 22를 켜 두고 PC에서 SSH로 접속하면, 키 교환부터 로그인까지 패킷이 줄줄이 찍힌다. 내용은 암호화돼 있어 읽을 수 없다는 것도 확인할 수 있다.

4. 전화 음성은 어떻게 패킷으로 이동하나

  1. 디지털화: 목소리(아날로그)를 1초에 8,000번 재서 8비트로 저장 → 64kbps. 1960년대 디지털 전화망(PCM)에서 정한 숫자로, 지금도 G.711 코덱이 그대로 쓴다
  2. 쪼개기: 20ms 분량(160바이트)씩 끊는다. 더 길게 끊으면 헤더 낭비는 줄지만 그만큼 늦게 출발해 대화가 어색해진다
  3. 헤더 붙이기: RTP(순서 · 시간) → UDP(포트) → IP(주소) → 이더넷(MAC)
  4. 이동: 스위치 · 라우터가 헤더만 보고 전달. 교환기(IP-PBX)가 상대 전화로 넘긴다
  5. 재생: 받는 쪽은 잠깐 모아 두었다가(지터 버퍼) 순서대로 재생한다

통화 연결과 음성은 다른 길: 전화를 걸고 · 받고 · 끊는 신호는 SIP(보통 5060번 포트), 실제 음성은 RTP(짝수 포트 범위)로 따로 흐른다. 그래서 방화벽에서 SIP만 열고 RTP 포트를 안 열면 "전화는 연결되는데 소리가 안 들리는" 장애가 난다.

왜 음성은 TCP가 아니라 UDP인가 TCP는 빠진 패킷을 다시 보내 달라고 하고 그 사이 뒤 패킷을 기다리게 한다. 음성에서 0.3초 늦게 온 조각은 이미 쓸모없다. 조금 빠지더라도(짧은 잡음) 제때 흘러가는 게 낫기 때문에 재전송이 없는 UDP를 쓴다.
녹취와 연결 ① 미러링: 스위치의 포트 미러링(SPAN)으로 통화 패킷을 복사해 녹취서버로 보낸다 — 통화에 영향이 없지만 스위치 설정과 암호화(SRTP) 여부가 관건. ② 교환기 직접 연동: 녹취서버가 SIP로 교환기에 녹취용 내선을 등록하고 교환기가 음성을 보내 준다 — 벤더 협조와 ACL 등록이 필요하다.

음성 패킷의 구조

헤더가 음성의 1/3쯤 된다. 그래서 채널 수가 많은 콜센터는 대역폭을 헤더까지 포함해 계산해야 한다(100채널 × 87kbps ≈ 8.7Mbps, 양방향이면 두 배).

핵심 정리

  • 패킷 = 쪼갠 데이터 + 헤더. 장비는 헤더만 보고 전달한다
  • 보낼 때 응용 → 전송(포트) → 네트워크(IP) → 링크(MAC) 순서로 헤더가 붙는다
  • tcpdump로 서버에서, Wireshark로 PC에서 본다. 상세 화면이 곧 캡슐화 그림이다
  • 음성은 20ms마다 RTP/UDP 패킷으로, 통화 신호는 SIP로 따로 흐른다. 녹취는 그 RTP를 복사하거나 받아서 만든다
