네트워크 기본

네트워크

1960s

Network

시대적 배경
컴퓨터가 기관마다 한 대뿐이던 시절, 멀리 있는 사람이 그 컴퓨터를 쓰려면 직접 찾아가거나 테이프를 들고 가야 했다.
그래서 생긴 문제
데이터와 계산 자원을 나눠 쓸 방법이 없어 같은 장비를 곳곳에 따로 사야 했고, 결과를 주고받는 데 며칠씩 걸렸다.
개념 · 역할
호스트들이 통신 매체와 네트워크 장비로 연결되어, 정해진 약속(프로토콜)에 따라 데이터를 주고받는 구조 전체.
헷갈리기 쉬운 점
길(선 · 장비)만이 네트워크가 아니다. 호스트와 약속까지 합쳐야 네트워크다.
지금 · 실무에서
인터넷은 수많은 네트워크를 다시 이은 "네트워크의 네트워크"다.

관련 그림: 네트워크의 구조와 분류

호스트

1969

Host

시대적 배경
ARPANET에서 사용자와 프로그램을 품고 서비스를 "맞이하는 주인" 역할을 한 대형 컴퓨터를 host라고 불렀다. 그 사이에서 전달만 하는 장비(IMP)는 따로 두었다.
그래서 생긴 문제
데이터를 만들고 쓰는 컴퓨터와, 전달만 하는 장비를 같은 이름으로 부르면 각자 할 일(처리 vs 전달)이 섞인다.
개념 · 역할
네트워크에 연결돼 데이터를 직접 보내거나 최종적으로 받는 끝단 장치. PC · 서버 · 스마트폰.
헷갈리기 쉬운 점
서버 · 클라이언트는 호스트의 역할 이름이다. 같은 노트북도 상황에 따라 둘 다 된다.
지금 · 실무에서
리눅스 hostname, /etc/hosts가 이 말에서 왔다.

그래프 (노드 · 간선)

1736

Graph · Node · Edge

시대적 배경
1736년 수학자 오일러가 쾨니히스베르크의 다리 7개를 한 번씩만 건널 수 있는지 풀면서, 땅을 점으로 · 다리를 선으로 바꿔 생각했다. 그래프 이론의 시작이다.
그래서 생긴 문제
지도 그림 그대로는 계산할 수 없다. "어디가 어디와 이어졌나"만 남겨야 경로 · 최단 거리 · 끊기는 지점을 셀 수 있다.
개념 · 역할
노드(점)와 노드를 잇는 간선(선)으로 이루어진 자료구조. 간선에 비용(가중치) · 방향을 붙일 수 있고, 인접 리스트나 인접 행렬로 저장한다.
헷갈리기 쉬운 점
"차트 그래프"가 아니다. 연결 관계를 나타내는 자료구조다.
지금 · 실무에서
라우터의 경로 계산, SNS 추천, 지도 길 찾기 모두 그래프 알고리즘이다. STAGE 3에서 다시 나온다.

토폴로지

1964

Topology

시대적 배경
폴 배런이 핵 공격에도 살아남는 통신망을 연구하며 중앙집중형 · 분산형을 그림으로 비교했다. 연결 모양이 생존성을 좌우한다는 것을 보여 줬다.
그래서 생긴 문제
모든 선이 한 중심으로 모이면 그 중심 하나가 무너질 때 전체가 끊긴다.
개념 · 역할
네트워크 장치를 어떤 모양으로 연결했는지(스타 · 버스 · 링 · 메시 · 트리).
헷갈리기 쉬운 점
물리적으로 선을 깐 모양과, 데이터가 실제로 흐르는 논리적 모양이 다를 수 있다.
지금 · 실무에서
집은 스타, 데이터센터 핵심부는 메시에 가깝게 이중화한다.

프로토콜

1969

Protocol

시대적 배경
ARPANET에서 서로 다른 회사의 컴퓨터를 이어야 했다. 연구자들이 회의록을 "의견 요청(RFC)" 문서로 돌리며 주고받는 규칙을 정했다. 외교 의전을 뜻하던 protocol이라는 말을 빌렸다.
그래서 생긴 문제
컴퓨터마다 데이터 형식과 순서가 달라서, 선은 이어져 있어도 서로 알아듣지 못했다.
개념 · 역할
통신하는 쪽끼리 미리 정한 약속: 데이터 형식, 주고받는 순서, 오류가 났을 때 할 일. HTTP · TCP · IP · SIP 모두 프로토콜이다.
헷갈리기 쉬운 점
프로토콜은 프로그램이 아니라 규칙이다. 그 규칙을 구현한 것이 프로그램이다.
지금 · 실무에서
인터넷 프로토콜은 지금도 RFC 문서로 공개 표준이 된다.

범위에 따른 분류

WAN

1950s~1969

Wide Area Network

시대적 배경
대형 컴퓨터가 비싸 한 곳에만 있었고, 멀리 떨어진 단말을 잇기 위해 전화 회선을 빌렸다(미국 방공망 SAGE, 1969년 ARPANET).
그래서 생긴 문제
수백 km 거리에는 직접 선을 깔 수 없고, 통신사 회선은 느리고 비쌌다.
개념 · 역할
도시 · 나라 · 대륙처럼 넓은 지역을 잇는 네트워크. 통신사가 깐 회선을 빌려 쓴다.
헷갈리기 쉬운 점
WAN은 기술 이름이 아니라 범위의 이름이다. 인터넷도 WAN의 한 형태다.
지금 · 실무에서
은행 대외계와 금융결제원은 전용회선(WAN)으로 연결된다.

관련 그림: 네트워크의 구조와 분류

LAN

1973

Local Area Network

시대적 배경
미니컴퓨터 · 워크스테이션이 늘며 한 건물 안에 컴퓨터가 여러 대가 됐다. 제록스 팔로알토 연구소가 이들과 레이저 프린터를 잇기 위해 이더넷을 만들었다.
그래서 생긴 문제
바로 옆 컴퓨터를 잇는 데도 느리고 비싼 전화 회선 방식을 쓸 이유가 없었다.
개념 · 역할
집 · 사무실 · 건물처럼 좁은 범위를 내가 직접 깐 선과 장비로 잇는 네트워크.
헷갈리기 쉬운 점
공유기 아래 192.168.x.x 주소를 쓰는 기기들이 보통 한 LAN이다.
지금 · 실무에서
고객사 서버실 안 = LAN. 장애 때 LAN 문제인지 회선(WAN) 문제인지부터 가른다.

관련 그림: 네트워크의 구조와 분류

MAN

1990

Metropolitan Area Network

시대적 배경
회사 · 대학 · 관공서가 도시 곳곳에 건물을 두면서 LAN보다 넓고 WAN보다 좁은 연결이 필요해졌다. IEEE가 1990년 도시 단위 표준을 정했다.
그래서 생긴 문제
건물 여러 곳을 잇기엔 LAN 기술은 거리가 짧고, WAN 회선은 너무 비쌌다.
개념 · 역할
도시 하나 정도 범위의 네트워크. 지자체 · 대학 캠퍼스 망 · 케이블 방송망.
헷갈리기 쉬운 점
지금은 기술이 섞여 LAN · MAN · WAN 경계가 흐리다. 범위를 말하는 용어로 이해하면 된다.
지금 · 실무에서
실무에서는 MAN이라는 말보다 "전용회선 · 본지점 망"이라고 많이 부른다.

이더넷

1973

Ethernet

시대적 배경
1973년 로버트 멧칼프가 제록스에서 만들었다. 하와이 대학의 무선망 ALOHAnet 아이디어(먼저 보내고 충돌하면 다시)를 케이블에 옮겼다. 이름은 빛을 전달한다고 믿었던 가상의 물질 "에테르"에서 왔다.
그래서 생긴 문제
한 케이블에 여러 컴퓨터가 붙으면 누가 언제 말할지 정해야 했다.
개념 · 역할
LAN에서 쓰는 대표 기술. 데이터를 프레임으로 감싸고 MAC 주소로 목적지를 찾는다. 1983년 IEEE 802.3 표준.
헷갈리기 쉬운 점
이더넷은 랜선 이름이 아니라 규칙(데이터 링크 계층)이다. 랜선은 그 규칙을 실어 나르는 매체다.
지금 · 실무에서
지금은 스위치 덕분에 충돌이 거의 없고, 속도는 10Mbps에서 수백 Gbps까지 올랐다.

교환 방식과 패킷

회선 교환

1878

Circuit Switching

시대적 배경
1878년 최초의 상업 전화 교환대가 생겼고, 교환원이 플러그로 두 전화를 직접 이었다. 1891년 자동 교환기가 특허를 받았다.
그래서 생긴 문제
모든 전화를 서로 직접 선으로 이으면 선 수가 폭발한다(100대면 4,950가닥).
개념 · 역할
통신 전에 두 끝 사이에 길(회선)을 잡고, 통신이 끝날 때까지 그 길을 독점하는 방식.
헷갈리기 쉬운 점
말이 없을 때도 길을 붙잡고 있어 데이터 통신에는 낭비가 크다.
지금 · 실무에서
옛 유선 전화망. 지금 콜센터 전화는 대부분 패킷(VoIP)으로 바뀌었다.

메시지 교환

1900s

Message Switching

시대적 배경
전신(전보) 시대, 전신국은 전문 하나를 통째로 받아 종이테이프에 저장했다가 다음 국으로 보냈다.
그래서 생긴 문제
회선을 잡아 두지 않으려니 중간 국이 메시지를 맡아 둘 수밖에 없었다.
개념 · 역할
메시지 전체를 중간 노드가 받아 저장한 뒤 다음 노드로 넘기는 저장 후 전달 방식.
헷갈리기 쉬운 점
패킷 교환도 저장 후 전달이지만, 작게 쪼개서 기다림이 짧다는 점이 다르다.
지금 · 실무에서
방식 자체는 거의 사라졌고, 이메일이 "맡겼다가 전달" 개념을 잇는다.

패킷 교환

1964~1969

Packet Switching

시대적 배경
배런(1964, 미국)과 데이비스(1965, 영국)가 각각 데이터를 작은 블록으로 쪼개 보내는 방식을 제안했고, 1969년 ARPANET이 이 방식으로 첫 메시지를 보냈다.
그래서 생긴 문제
컴퓨터 데이터는 띄엄띄엄 몰려 나와서, 회선을 잡아 두면 대부분 시간이 놀았다.
개념 · 역할
데이터를 패킷으로 쪼개 각 패킷이 독립적으로 길을 찾아가고, 받는 쪽에서 다시 조립하는 방식.
헷갈리기 쉬운 점
패킷 순서가 바뀌거나 사라질 수 있어 TCP 같은 장치가 따로 필요하다.
지금 · 실무에서
인터넷의 기본 원리. 인터넷 전화 · 녹취 RTP도 패킷 교환이다.

관련 그림: 네트워크의 구조와 분류

패킷

1965

Packet

시대적 배경
도널드 데이비스가 데이터 조각을 "작은 소포"라는 뜻의 packet으로 이름 붙였다. 여러 언어로 옮기기 쉬운 짧은 단어를 골랐다.
그래서 생긴 문제
큰 데이터를 통째로 보내면 길을 오래 붙잡고, 조금만 깨져도 전체를 다시 보내야 했다.
개념 · 역할
전송을 위해 쪼갠 데이터 조각과, 그 앞에 붙인 헤더(주소 · 순서 등)를 합친 단위.
헷갈리기 쉬운 점
엄밀히는 계층마다 세그먼트 · 패킷 · 프레임으로 다르게 부르지만, 일상에서는 모두 패킷이라 한다.
지금 · 실무에서
tcpdump · Wireshark로 직접 볼 수 있다.

관련 그림: 패킷

헤더 · 페이로드

1970s

Header · Payload

시대적 배경
우편 봉투에 주소를 적듯, 패킷도 내용과 별도로 배달 정보를 담는 칸이 필요했다. 계층마다 자기 헤더를 붙이는 구조가 1970년대 프로토콜 설계에서 자리 잡았다.
그래서 생긴 문제
중간 장비가 배달하려고 내용을 매번 열어 보면 느리고 사생활도 침해된다.
개념 · 역할
헤더 = 패킷 앞에 붙은 배달 정보(주소 · 포트 · 순서). 페이로드 = 실제로 전하려는 내용.
헷갈리기 쉬운 점
헤더도 대역폭을 먹는다. 작은 음성 패킷은 헤더가 내용의 1/3쯤 된다.
지금 · 실무에서
Wireshark 상세 화면이 헤더를 계층별로 펼쳐 보여 준다.

관련 그림: 패킷

계층과 주소

OSI 7계층

1984

OSI Reference Model

시대적 배경
1970년대 IBM · DEC 등 회사마다 자기만의 네트워크 방식을 써서 서로 연결이 안 됐다. 국제표준화기구(ISO)가 1984년 통신을 7단계로 나눈 공통 참조 모델을 발표했다.
그래서 생긴 문제
통신 기능 전체를 한 덩어리로 만들면, 선 하나만 바꿔도 프로그램 전체를 다시 만들어야 했다.
개념 · 역할
통신을 물리 · 데이터 링크 · 네트워크 · 전송 · 세션 · 표현 · 응용 7단계로 나눈 참조 모델. 각 계층은 아래 계층의 기능을 쓰고 위 계층에 기능을 제공한다.
헷갈리기 쉬운 점
OSI 7계층 자체가 동작하는 프로그램은 아니다. 설명하고 비교하기 위한 기준표다.
지금 · 실무에서
실제 인터넷은 TCP/IP 4계층으로 동작하지만, "L2 · L3 · L4 · L7"이라는 말은 OSI 번호를 쓴다.

관련 그림: 패킷

TCP/IP 4계층

1974~1983

TCP/IP Model

시대적 배경
1974년 빈트 서프와 밥 칸이 서로 다른 네트워크를 잇는 방법(TCP/IP) 논문을 냈고, 1983년 1월 1일 ARPANET이 TCP/IP로 전환했다.
그래서 생긴 문제
서로 다른 기술을 쓰는 네트워크들을 하나로 이어야 했다.
개념 · 역할
실제 인터넷이 쓰는 4단계 구조: 네트워크 접근(링크) · 인터넷(IP) · 전송(TCP/UDP) · 응용(HTTP 등).
헷갈리기 쉬운 점
OSI 7계층의 세션 · 표현 · 응용은 TCP/IP에서 응용 계층 하나로 묶인다.
지금 · 실무에서
지금 우리가 쓰는 모든 인터넷 통신의 구조다.

관련 그림: 패킷

캡슐화

1970s

Encapsulation

시대적 배경
계층 구조를 만들면서, 각 계층이 위에서 받은 데이터를 건드리지 않고 자기 정보만 앞에 붙이는 방식이 정해졌다.
그래서 생긴 문제
각 계층이 데이터 내용을 직접 고치면 계층끼리 서로 얽혀 독립성이 깨진다.
개념 · 역할
보낼 때 위 계층 데이터 앞에 각 계층의 헤더를 차례로 붙이는 것. 받을 때 아래부터 하나씩 떼는 것은 역캡슐화.
헷갈리기 쉬운 점
데이터가 바뀌는 게 아니라 겉에 정보가 덧붙는 것이다.
지금 · 실무에서
tcpdump · Wireshark 상세 화면에서 이더넷 ▸ IP ▸ TCP ▸ 데이터로 그대로 보인다.

관련 그림: 패킷

MAC 주소

1970s~1980

MAC Address

시대적 배경
이더넷 케이블에 여러 컴퓨터가 붙자, 같은 선 위에서 서로를 구분할 이름이 필요해졌다. 제록스가 시작한 48비트 주소 체계를 IEEE가 이어받았다.
그래서 생긴 문제
같은 LAN 안에서 프레임이 누구에게 가는지 구분할 방법이 없었다.
개념 · 역할
네트워크 카드(NIC)에 붙은 48비트 고유 주소(예: 3c:52:82:aa:bb:cc). 같은 LAN 안에서 바로 옆 장비에게 보낼 때 쓴다.
헷갈리기 쉬운 점
MAC 주소는 라우터를 넘을 때마다 바뀐다(구간마다 새 이더넷 헤더). 끝까지 가는 주소는 IP다.
지금 · 실무에서
스위치는 MAC 주소 표를 보고 포트를 고른다. ip a 명령의 link/ether 값.

관련 그림: 네트워크 장비

IP 주소

1981

IP Address

시대적 배경
여러 네트워크를 이은 인터넷에서는 MAC처럼 납작한 번호로는 길을 찾을 수 없었다. 1981년 RFC 791이 네트워크 부분 + 호스트 부분으로 된 32비트 주소(IPv4)를 정했다.
그래서 생긴 문제
세계의 모든 MAC 주소 위치를 라우터가 다 외울 수는 없다.
개념 · 역할
네트워크 계층에서 장치를 가리키는 주소. IPv4는 32비트(192.168.50.10), IPv6는 128비트. /24 같은 표기는 앞 몇 비트가 네트워크 부분인지 뜻한다.
헷갈리기 쉬운 점
IP는 장치가 아니라 연결된 위치에 붙는다. 노트북을 다른 Wi-Fi로 옮기면 IP가 바뀐다.
지금 · 실무에서
IPv4 주소가 모자라서 NAT · 사설 IP가 생겼다.

관련 그림: 패킷

포트

1981

Port

시대적 배경
한 컴퓨터에서 웹서버 · 메일 · SSH가 동시에 돌기 시작했다. 1981년 TCP 표준이 16비트 포트 번호로 프로그램을 구분하게 했다.
그래서 생긴 문제
IP 주소로는 컴퓨터까지만 찾아간다. 그 안의 어느 프로그램에게 줄지 알 수 없다.
개념 · 역할
한 컴퓨터 안에서 통신하는 프로그램을 구분하는 번호. IP가 건물 주소라면 포트는 호수.
헷갈리기 쉬운 점
포트는 물리적인 구멍이 아니라 숫자다. 0.0.0.0:22는 "모든 IP의 22번에서 기다림"이라는 뜻.
지금 · 실무에서
ss -tlnp로 어떤 프로그램이 어느 포트에서 기다리는지 본다. 방화벽 신청서의 핵심 항목.

관련 그림: 왜 네트워크를 공부하나

유니 · 브로드 · 멀티 · 애니캐스트

1970s~1993

Unicast · Broadcast · Multicast · Anycast

시대적 배경
이더넷은 처음부터 "모두에게(브로드캐스트)"를 지원했고, 1980년대 멀티캐스트, 1993년 애니캐스트가 정의됐다.
그래서 생긴 문제
같은 데이터를 여러 곳에 보낼 때 하나씩 보내면 같은 패킷이 수백 번 흐른다.
개념 · 역할
유니캐스트 1:1, 브로드캐스트 1:같은 LAN 전부, 멀티캐스트 1:가입한 그룹, 애니캐스트 1:가장 가까운 하나.
헷갈리기 쉬운 점
브로드캐스트는 라우터를 넘지 않는다. LAN 안에서만 퍼진다.
지금 · 실무에서
DHCP · ARP는 브로드캐스트, IPTV · 아파트 방송은 멀티캐스트, DNS 루트 서버는 애니캐스트.

관련 그림: 네트워크의 구조와 분류

장비와 보안

허브

1980s

Hub

시대적 배경
10BASE-T 이더넷이 보급되며, 굵은 동축 케이블 대신 허브 하나에 랜선을 별 모양으로 꽂는 방식이 퍼졌다.
그래서 생긴 문제
허브는 주소를 몰라서 받은 신호를 모든 포트로 내보냈다.
개념 · 역할
받은 전기 신호를 키워 모든 포트로 똑같이 내보내는 1계층 장비.
헷갈리기 쉬운 점
사무실의 "허브"라 부르는 장비는 대부분 실제로는 스위치다.
지금 · 실무에서
지금은 거의 쓰지 않는다. 패킷 분석용으로 일부러 쓰기도 한다.

관련 그림: 네트워크 장비

스위치

1990

Switch

시대적 배경
1990년 무렵 칼파나사가 첫 이더넷 스위치를 내놓았다. 허브의 충돌 문제를 MAC 주소 학습으로 풀었다.
그래서 생긴 문제
허브에 사람이 늘수록 충돌이 늘어 LAN이 느려졌다.
개념 · 역할
MAC 주소 표를 만들어 프레임을 목적지 포트로만 보내는 2계층 장비. 같은 LAN 안을 잇는다.
헷갈리기 쉬운 점
스위치는 다른 네트워크로 길을 찾지 않는다. 그건 라우터(또는 L3 스위치)의 일이다.
지금 · 실무에서
포트 미러링(SPAN) 기능으로 통화 패킷을 복사해 녹취서버로 보낸다.

관련 그림: 네트워크 장비

라우터

1969

Router

시대적 배경
ARPANET의 IMP가 조상이다. 1980년대 여러 프로토콜을 잇는 상용 라우터가 나오며 회사 · 대학 망을 인터넷에 연결했다.
그래서 생긴 문제
서로 다른 네트워크 사이에서 패킷을 어느 쪽으로 보낼지 정할 장비가 필요했다.
개념 · 역할
IP 주소와 라우팅 표를 보고 패킷을 다음 네트워크로 넘기는 3계층 장비. LAN의 출구가 기본 게이트웨이다.
헷갈리기 쉬운 점
집 공유기는 라우터 + 스위치 + NAT + DHCP + 무선 AP를 한 상자에 넣은 것이다.
지금 · 실무에서
traceroute로 패킷이 거치는 라우터를 하나씩 볼 수 있다.

관련 그림: 네트워크 장비

방화벽

1988

Firewall

시대적 배경
1988년 모리스 웜이 인터넷의 컴퓨터 수천 대를 감염시키며 아무 연결이나 받아 주는 위험이 드러났다. 같은 해 패킷을 규칙으로 걸러 내는 패킷 필터가 등장했다. 이름은 건물의 불을 막는 방화벽에서 왔다.
그래서 생긴 문제
인터넷에 연결된 모든 서버가 모든 포트를 열어 두고 있었다.
개념 · 역할
IP · 포트 · 연결 상태 규칙에 따라 패킷을 통과시키거나 막는 장비 · 소프트웨어(firewalld도 방화벽이다).
헷갈리기 쉬운 점
차단 방식에 따라 증상이 다르다. 조용히 버리면 timed out, 거절을 알리면 refused가 뜬다.
지금 · 실무에서
고객사 설치 전 방화벽 오픈 신청이 필수다. 홈서버도 공유기 + firewalld 두 겹이다.

관련 그림: 실무 아키텍처

DMZ

1990s

Demilitarized Zone

시대적 배경
1990년대 회사들이 웹서버를 인터넷에 공개하면서, 외부에 보여야 하는 서버와 숨겨야 하는 내부 시스템을 한 곳에 둘 수 없었다. 군사 용어 비무장지대를 빌렸다.
그래서 생긴 문제
웹서버가 내부망에 있으면 웹서버 하나만 뚫려도 DB까지 바로 닿는다.
개념 · 역할
외부 방화벽과 내부 방화벽 사이, 외부 접근이 필요한 서버만 두는 완충 구역.
헷갈리기 쉬운 점
DMZ 서버도 안전한 곳이 아니라 "뚫려도 피해가 덜한 곳"이다.
지금 · 실무에서
은행은 인터넷뱅킹 웹서버 · 중계서버를 DMZ에 둔다.

관련 그림: 실무 아키텍처

NAT

1994

Network Address Translation

시대적 배경
IPv4 주소(약 43억 개)가 1990년대 인터넷 폭증으로 모자라기 시작했다. 1994년 NAT가 제안되고, 1996년 내부용 사설 IP 대역(192.168.x.x 등)이 정해졌다.
그래서 생긴 문제
집 · 회사의 모든 기기에 공인 IP를 하나씩 줄 수 없었다.
개념 · 역할
패킷의 IP(와 포트)를 바꿔 주는 기술. 공유기가 내부 사설 IP를 공인 IP 하나로 바꿔 내보내고, 돌아오는 응답을 원래 기기에 돌려준다.
헷갈리기 쉬운 점
NAT는 보안 장비가 아니지만, 결과적으로 외부에서 내부로 바로 들어오기 어렵게 만든다.
지금 · 실무에서
포트포워딩(외부 포트 → 내부 22)도 NAT 설정이다.

관련 그림: 네트워크 장비

망분리

2013

Network Separation

시대적 배경
2013년 3월 시중 은행 전산망이 마비된 3·20 사이버테러 뒤, 금융위원회가 2014년 말까지 금융회사 전산망 분리를 의무화했다.
그래서 생긴 문제
업무 PC가 인터넷에서 악성코드를 받으면 내부 전산 시스템까지 그대로 퍼졌다.
개념 · 역할
내부 업무망과 인터넷망을 물리적(PC · 선 분리) 또는 논리적(가상화)으로 나누는 보안 정책. 전자금융감독규정 제15조가 근거.
헷갈리기 쉬운 점
망분리는 만능이 아니다. 내부자 유출 · 반입 매체 같은 다른 위험은 따로 막아야 한다.
지금 · 실무에서
2024년 로드맵 이후 생성형 AI · SaaS · 연구개발망부터 단계적으로 완화 중. 금융권 설치 시 오프라인 패키지 준비가 필요한 이유.

관련 그림: 실무 아키텍처

음성 통신

VoIP

1995

Voice over IP

시대적 배경
1995년 이스라엘 회사가 인터넷으로 통화하는 프로그램을 내놓았다. 2000년대 기업 교환기가 IP-PBX로 바뀌며 콜센터도 VoIP로 넘어갔다.
그래서 생긴 문제
전화망(회선)과 데이터망(인터넷)을 따로 운영하니 비용이 두 배였다.
개념 · 역할
음성을 디지털로 바꿔 IP 패킷으로 주고받는 전화 기술. 신호는 SIP, 음성은 RTP로 보낸다.
헷갈리기 쉬운 점
VoIP 통화 품질은 대역폭보다 지연 · 지터 · 손실에 더 민감하다.
지금 · 실무에서
콜센터 교환기(IP-PBX)와 녹취 · STT가 모두 이 위에서 동작한다.

관련 그림: 패킷

코덱 (G.711)

1972

Codec

시대적 배경
1960년대 디지털 전화망이 음성을 1초에 8,000번 재서 8비트로 저장하는 방식(PCM, 64kbps)을 썼고, 1972년 ITU가 이를 G.711로 표준화했다.
그래서 생긴 문제
아날로그 음성을 그대로 보내면 거리가 멀수록 잡음이 쌓이고 컴퓨터가 다룰 수 없었다.
개념 · 역할
음성 · 영상을 디지털 데이터로 바꾸고(인코딩) 되돌리는(디코딩) 규칙과 프로그램. G.711 · G.729 · Opus 등.
헷갈리기 쉬운 점
압축이 강한 코덱(G.729)은 대역폭을 아끼지만 음질이 떨어져 STT 인식률에 영향을 준다.
지금 · 실무에서
녹취 · STT는 대부분 G.711(8kHz)을 받아 처리한다. 코덱이 다르면 디코딩부터 실패한다.

관련 그림: 패킷

RTP

1996

Real-time Transport Protocol

시대적 배경
인터넷으로 음성 · 영상을 실시간으로 보내려는 시도가 늘자 1996년 IETF가 RTP를 표준으로 정했다.
그래서 생긴 문제
UDP만으로는 순서가 뒤바뀌거나 빠진 패킷을 알 수 없고, 언제 재생할지도 몰랐다.
개념 · 역할
UDP 위에서 실시간 음성 · 영상을 나르는 프로토콜. 헤더에 순서 번호 · 타임스탬프 · 코덱 종류 · 발신원(SSRC)을 담는다.
헷갈리기 쉬운 점
RTP는 재전송을 하지 않는다. 늦은 음성은 버리는 게 낫기 때문이다.
지금 · 실무에서
녹취서버는 RTP 패킷을 순서 번호대로 이어 wav를 만든다.

SIP

1999

Session Initiation Protocol

시대적 배경
1999년 IETF가 인터넷에서 통화를 걸고 받고 끊는 신호 규칙으로 SIP를 정했다. HTTP를 본떠 글자 기반 요청 · 응답으로 만들었다.
그래서 생긴 문제
음성을 보낼 길(RTP)은 생겼지만, 누구에게 전화를 걸고 어떤 코덱 · 포트로 받을지 정할 방법이 필요했다.
개념 · 역할
통화(세션)를 시작 · 변경 · 종료하는 신호 프로토콜. 보통 5060번 포트. 등록(REGISTER)으로 내선을 교환기에 알린다.
헷갈리기 쉬운 점
SIP는 음성을 나르지 않는다. 음성은 RTP가 따로 나른다. 그래서 SIP만 열면 "연결은 되는데 소리가 없다".
지금 · 실무에서
교환기 직접 연동 녹취는 녹취서버가 SIP로 내선을 등록해 음성을 받는 방식이다.

관련 그림: 패킷

지터

1990s

Jitter

시대적 배경
패킷 교환 망에서 실시간 음성을 보내기 시작하면서, 패킷마다 도착 간격이 들쭉날쭉한 문제가 드러났다.
그래서 생긴 문제
20ms마다 보낸 패킷이 15ms · 40ms · 5ms 간격으로 도착하면 소리가 빨라졌다 끊겼다 한다.
개념 · 역할
패킷 도착 간격(지연)이 흔들리는 정도. 지터 버퍼로 흡수하지만 버퍼가 크면 대화가 늦어진다.
헷갈리기 쉬운 점
지연(늦게 옴)과 지터(늦는 정도가 들쭉날쭉)는 다르다.
지금 · 실무에서
Wireshark RTP Stream Analysis에서 지터 · 손실을 수치로 본다. 녹취 음질 · STT 인식률 장애 분석 지표.
