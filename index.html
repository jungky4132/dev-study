2026–2027 개발자 기본기 학습 기록 · STAGE별 정리와 그림

STAGE 1 · 컴퓨터 시스템 + 리눅스 기초18개
  • STAGE 1 용어 사전STAGE 1 그림에 나오는 용어 166개(핵심 104 + 설명 속 기초 62)를, 그 개념이 왜 생길 수밖에 없었는지(시대 → 문제 → 개념) 순서로 정리
  • CPU 레지스터 한 장 그림if 문 한 줄이 CPU 안에서 어떻게 실행되는지(비교 → 결과 표시 → 건너뛰기), 장치가 끼어들 때(인터럽트) 무슨 일이 일어나는지, 프로그램이 쓰는 주소가 실제 메모리 위치로 어떻게 바뀌는지(MMU)를 레지스터 하나하나까지 따라가기
  • SSD 셀 · 페이지 · 블록과 수명SSD는 왜 덮어쓰지 못하고 블록 단위로만 지우는지, 그리고 지울 때마다 수명이 줄어드는 과정
  • 보조기억장치 정리SSD 종류(셀 하나에 1~4비트)별 차이와 용도, 빠른 쓰기 영역(SLC 캐시), 하드디스크의 역사, 용어 정리
  • RAID 정리디스크 여러 개를 묶어 더 빠르게, 또는 하나가 고장 나도 데이터를 잃지 않게 쓰는 방법과 그 등장 배경
  • 입출력 방식 한 장 그림키보드 · 디스크 같은 장치와 컴퓨터가 데이터를 주고받는 세 가지 방법(CPU가 계속 확인 · 장치가 알려 줌 · 전용 장치가 대신 옮김)과 CPU 부담의 차이
  • 데이터와 문자 인코딩 한 장 그림컴퓨터가 숫자를 0과 1로 나타내는 방법(음수 포함)과 글자를 바이트로 저장하는 규칙, 그리고 한글이 깨지는 이유
  • 메모리 계층과 캐시 한 장 그림빠른 메모리는 작고 비싸서 여러 층으로 나눠 쓰는 이유, CPU가 데이터를 찾는 순서(캐시 → RAM), 작은 캐시가 잘 맞는 이유
  • MMU 한 장 그림프로그램이 쓰는 주소가 실제 메모리 위치로 바뀌는 과정과, 다른 프로그램의 영역을 침범하지 못하게 막는 방법(메모리 보호)
  • 시스템 콜과 사용자 · 커널 모드 한 장 그림일반 프로그램이 하드웨어를 직접 만지지 못하게 막는 이유(사용자 모드 · 커널 모드)와, 파일 읽기 같은 일을 운영체제에 부탁하는 방법(시스템 콜)
  • 운영체제 · 커널 · 인터럽트 질문 정리운영체제 전체가 커널 영역에 들어가는지, root와 커널 모드는 같은지, 시스템 콜은 왜 인터럽트인지 등 강의를 들으며 생긴 질문 8개를 그림 3장으로 정리
  • 프로세스와 스레드 한 장 그림실행 중인 프로그램(프로세스)이 메모리를 어떻게 나눠 쓰고 운영체제가 어떻게 관리하는지, 프로세스가 어떤 상태를 오가고 어떻게 태어나는지(fork · exec), 한 프로세스 안에서 일을 나누는 스레드는 무엇을 함께 쓰는지, 스레드 하나가 죽으면 프로세스도 죽는지
  • CPU 스케줄링 한 장 그림CPU는 하나인데 실행할 프로그램이 여러 개일 때 누구를 먼저 실행할지 정하는 방법들(먼저 온 순서 · 짧은 것 먼저 · 돌아가며)을 같은 예시로 비교
  • 코어 · 스레드 · 스케줄링 질문 정리물리 · 논리 코어와 프로세스 · 스레드는 어떤 관계인지, 서버 CPU는 코어당 스레드가 몇 개인지, STT 채널은 코어와 어떻게 연결되는지, CPU 스케줄링이 실무에서 왜 중요한지 등 질문 9개를 그림 3장으로 정리
  • 파일 시스템과 inode 한 장 그림경로(/etc/hostname)만으로 디스크 여기저기 흩어진 파일 내용을 찾아가는 과정: 디렉터리 → inode(파일 정보 카드) → 데이터 블록
  • 리눅스 권한 (755) 한 장 그림ls -l에 보이는 -rwxr-xr-x가 무슨 뜻인지, 755 같은 숫자로 바꾸는 법, 누가 어떤 파일을 읽고 고치고 실행할 수 있는지
  • systemd와 패키지 관리 한 장 그림리눅스에서 서비스(sshd 등)를 켜고 끄고 부팅 때 자동으로 띄우는 방법(systemd)과, 프로그램을 설치하는 방법(rpm · dnf)
  • STAGE 1 관문 정리 · 핵심 6문항과 꼬리 질문관문 점검에서 나온 6문항(프로세스와 스레드 · 권한 755 · 시스템 콜 · 캐시 · 한글 깨짐 · 서비스 자동 시작)의 최종 답과, 답하다 막혔던 꼬리 질문(크롬 탭 · Apache 403 · printf → write · 2차원 배열과 캐시 등) 정리
STAGE 2 · 네트워크 기초6개
  • 왜 개발자가 네트워크를 공부해야 하나요청 하나가 브라우저에서 DB까지 지나가는 길과 구간별 장애 증상(timed out vs refused), 성능 · 보안 · 고객사 방화벽 신청 · 녹취 업무와의 연결
  • 네트워크의 구조와 분류호스트 · 장비 · 매체, 그래프 자료구조(인접 리스트 · 행렬 · 최단 경로)와 토폴로지, LAN · MAN · WAN과 회선 · 메시지 · 패킷 교환으로 나눈 이유와 역사
  • 패킷: 개념 · 구조 · 보는 법 · 음성 패킷데이터를 쪼개는 이유, 캡슐화 구조, tcpdump · Wireshark로 보는 법, 전화 음성이 RTP 패킷으로 흐르고 녹취되는 과정
  • 네트워크 장비 종류와 역할계층별로 장비가 무엇을 보고 판단하는지, 허브와 스위치의 차이, 집 공유기에 들어 있는 기능들
  • 실무 네트워크 아키텍처와 금융권 구성DMZ · 내부망 · 관리망 기본 구성, 은행의 채널계 · 계정계 · 정보계 · 대외계와 망분리(2013~2026), STT · 녹취 서버의 자리
  • OSI · TCP/IP · 세션 질문 정리OSI 모델을 만든 역사적 이유, 계층을 나누는 진짜 이유, 학교에서 "왜"를 안 가르친 이유, 세션의 정확한 뜻과 실무의 여러 세션, TCP/IP 모델이 따로 있는 이유를 그림 5장으로 정리
  • STAGE 2 용어 사전 · 네트워크네트워크 용어 34개를 시대 → 문제(그림) → 개념 · 역할 → 실무 순서로 정리
