CPU 레지스터 한 장 그림

if 문 한 줄이 CPU 안에서 어떻게 실행되는지(비교 → 결과 표시 → 건너뛰기), 장치가 끼어들 때(인터럽트) 무슨 일이 일어나는지, 프로그램이 쓰는 주소가 실제 메모리 위치로 어떻게 바뀌는지(MMU)를 레지스터 하나하나까지 따라가기 · STAGE 1 컴퓨터 시스템

이 그림이 따라가는 예시 · if 문 한 줄

프로그램에 쓴 if (a == b) { … } 한 줄은 CPU 안에서 명령어 두 개로 바뀝니다. a는 R1, b는 R2라는 레지스터에 들어 있고, 같을 때 실행할 코드는 메모리 2000번지에 있다고 가정합니다.

  1. CMP R1, R2 = “두 값을 비교해라.” ALU가 R1에서 R2를 빼 보고, 결과가 0인지(같은지)만 플래그 레지스터에 표시합니다. 같으면 Z = 1, 다르면 Z = 0이고, 뺀 값 자체는 버립니다.
  2. JE 2000 = “같으면(Jump if Equal) 2000번지로 건너뛰어라.” 제어장치가 방금 남긴 표시(Z)를 보고, 같으면 다음에 실행할 위치(PC)를 2000으로 바꾸고, 다르면 원래 순서대로 다음 명령어를 실행합니다.

즉 if는 “비교해서 결과를 표시해 두기 → 그 표시를 보고 다음에 갈 곳 정하기” 두 단계입니다. 아래 그림의 1~7단계가 이 과정을 레지스터 하나하나까지 보여 줍니다.

MMU 확대 · 베이스 레지스터와 한계 레지스터 (섹션 7)
프로그램은 자기 안에서의 위치(논리 주소)만 압니다. MMU가 한계를 검사하고 베이스 레지스터(프로그램 시작 주소)를 더해 메모리의 진짜 위치(물리 주소)로 바꿉니다.
메모리 맵 입출력 자세히 보기 · 내가 이해한 것과 바로잡을 것 (섹션 9 입출력장치)

한 문장으로: 장치를 조종하는 레지스터에 메모리처럼 주소를 붙여서, CPU가 메모리를 읽고 쓰는 것과 똑같은 방법으로 장치를 다루게 하는 방식이다. 위 그림의 18 · 19단계를 자세히 푼 것이다.

비유: 아파트 호수 목록(주소 지도)에서 대부분은 집(RAM)이지만, 몇몇 호수는 집이 아니라 관리사무소 창구(장치 레지스터)다. 우편물(데이터)을 보내는 방법은 똑같고, 우체국(주소 디코더)이 호수를 보고 집으로 갈지 창구로 갈지 나눈다.

예시로 따라가기: 키보드에서 눌린 키 값 읽기
  1. 부팅 때 (BIOS · UEFI) 펌웨어가 키보드 컨트롤러에 주소 구간 F000~F0FF를 배정하고, 시작 주소 F000을 장치의 BAR에 적는다.
  2. 운영체제 → 드라이버 운영체제가 이 배정 정보를 관리하고, 키보드 드라이버에게 “네 장치는 F000부터”라고 알려 준다.
  3. 드라이버의 계산 데이터 레지스터는 시작 주소에서 4칸 떨어져 있으므로 F000 + 4 = F004. 드라이버 코드는 MOV R1, [F004]처럼 메모리를 읽는 것과 똑같은 명령어를 쓴다.
  4. CPU 주소 F004를 MAR에 넣고 주소 버스로 내보낸다. CPU는 이 주소가 RAM인지 장치인지 신경 쓰지 않는다.
  5. 주소 디코더 F004가 RAM 구간(0000~EFFF)이 아니라 키보드 구간이므로 RAM 대신 키보드 컨트롤러로 연결한다.
  6. 값이 돌아옴 키보드 컨트롤러의 데이터 레지스터에 있던 눌린 키 값이 데이터 버스를 타고 MBR로 들어오고, R1에 저장된다.

주소 F000 · F004와 구간 크기는 설명용 예시다. 실제 주소는 컴퓨터마다 부팅 때 정해진다.

맞게 이해한 것 6가지
  1. 드라이버는 통역사다
    운영체제는 “이 장치에서 읽어라 · 써라” 같은 공통 요청만 한다. 드라이버가 그 요청을 장치마다 다른 레지스터 조작(어느 주소의 레지스터에 어떤 값을 쓸지)으로 바꿔 준다.
  2. 메모리 맵은 주소 지도를 나눠 쓰는 것이다
    CPU가 쓸 수 있는 주소 범위(주소 공간)를 RAM과 장치 레지스터가 구간별로 나눠 가진다. 위 그림에서는 0000~EFFF가 RAM, F000~F0FF가 키보드 컨트롤러다.
  3. MAR은 장치 주소도 실어 나른다
    CPU 입장에서는 RAM이든 장치든 똑같다. 같은 명령어(MOV · LOAD)로 주소를 MAR에 넣고, 같은 주소 버스로 내보낸다.
  4. 주소 지도는 회로와 관리 정보로 이뤄진다
    실제로 RAM으로 보낼지 장치로 보낼지 가르는 것은 칩셋의 주소 디코더(회로)이고, 어느 구간을 어느 장치에 줄지는 펌웨어와 운영체제가 정한 정보다.
  5. BIOS · UEFI가 정하고, OS가 관리하고, 드라이버가 쓴다
    부팅 때 펌웨어가 장치마다 주소 구간을 배정해 장치의 BAR에 적는다. 운영체제가 그 정보를 넘겨받아 관리하고, 드라이버는 배정받은 구간만 쓴다.
  6. 장치 레지스터는 베이스 + 오프셋으로 찾는다
    배정받은 시작 주소(F000, BAR에 적힘)에 레지스터별 오프셋(데이터 레지스터는 +4)을 더해 F004를 만든다. 섹션 5의 “베이스 레지스터 + 오프셋”과 같은 계산이다.
바로잡을 것 6가지
  1. 오해 RAID처럼 RAM과 장치를 하나로 합친다
    실제 합치는 것이 아니라 주소 번호만 나눠 쓴다.
    왜 장치 레지스터는 데이터를 쌓아 두는 저장 공간이 아니라 장치를 조종하는 창구라서 용량이 합쳐지지 않는다. 오히려 장치가 주소를 차지하는 만큼 RAM이 쓸 주소가 줄어든다(아래 32비트 예시).
  2. 오해 주소 지도(매핑 표)가 CPU 레지스터 하나에 들어 있다
    실제 한곳에 있지 않고 여러 곳에 나뉘어 있다.
    왜 장치의 BAR, 칩셋(주소 디코더) 설정, 펌웨어가 운영체제에 넘기는 메모리 지도(예: UEFI 메모리 맵), 운영체제 커널의 자료구조에 나뉘어 있다.
  3. 오해 MAR이 주소 지도를 들고 있다
    실제 MAR은 지금 접근할 주소 하나만 잠깐 담는다.
    왜 명령어 하나를 처리하는 동안만 그 주소(F004)를 담고, 다음 접근 때 바로 다른 주소로 바뀐다. 지도를 보관하는 장소가 아니다.
  4. 오해 그 베이스는 CPU의 베이스 레지스터다
    실제 BAR(Base Address Register)는 장치 안에 있는 레지스터다.
    왜 원본 시작 주소는 장치의 BAR에 있다. 드라이버는 운영체제가 알려 준 시작 주소를 CPU의 레지스터에 올려 계산에 쓸 뿐이다. 이름은 둘 다 “베이스”지만 위치가 다르다.
  5. 오해 입출력 방식(메모리 맵 · 고립형)은 CPU가 정한다
    실제 CPU는 방식을 지원할 뿐이고, 무엇으로 접근할지는 장치와 버스 규격이 정한다.
    왜 x86 CPU는 두 방식을 모두 지원한다. 오래된 장치는 IN · OUT(고립형)을 쓰기도 했고, 요즘 PCIe 장치는 대부분 메모리 맵 방식을 쓴다.
  6. 오해 장치 컨트롤러는 윈도우의 “장치 관리자” 같은 것이다
    실제 장치 컨트롤러는 장치에 붙은 하드웨어 칩이다.
    왜 윈도우의 장치 관리자는 운영체제가 인식한 장치와 드라이버를 보여 주는 관리 프로그램(소프트웨어)일 뿐이다. 레지스터를 가진 실제 칩이 장치 컨트롤러다.
예: 32비트 PC에 RAM 4GB를 꽂아도 약 3~3.5GB만 보였던 이유
32비트 CPU의 주소 지도는 4GB(2의 32제곱)가 전부다. 그런데 그래픽 카드 같은 장치 레지스터가 그 지도의 위쪽 일부를 차지하니, 그 구간과 겹치는 RAM은 가리킬 번호가 없어 쓸 수 없었다. 주소를 “나눠 쓴다”는 말의 실제 결과다.
