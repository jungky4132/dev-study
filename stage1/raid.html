RAID 정리

개념과 등장 배경, 패리티로 복구하는 원리, RAID 레벨이 늘어난 이유 · STAGE 1 컴퓨터 시스템 (보조기억장치)

1. RAID란

RAID(Redundant Array of Independent Disks)는 디스크 여러 개를 하나처럼 묶어 속도를 높이거나, 일부가 고장 나도 데이터를 지키는 기술입니다. 처음 이름은 Redundant Array of Inexpensive Disks, 즉 "싼 디스크로 만든 중복 배열"이었습니다.

2. 왜 필요했나 · 역사적 배경

1980년대 메인프레임은 크고 비싼 디스크 한 대(SLED)를 썼습니다. 같은 시기 PC용 소형 디스크는 훨씬 싸졌고, 버클리 대학 연구진은 "싼 디스크를 여러 대 묶으면 더 싸고 빠르지 않을까?"라고 제안했습니다. 그런데 디스크가 많아지면 그중 하나가 고장 날 확률도 커지기 때문에, 중복(Redundancy)을 넣어야 했습니다. 이것이 RAID의 R입니다.

3. 패리티 · 복구의 원리

패리티는 XOR(배타적 논리합)로 만든 검산 값입니다. 같은 자리의 비트를 모두 XOR하면 패리티가 나옵니다. 1의 개수가 홀수면 1, 짝수면 0입니다. XOR은 순서를 바꿔도 결과가 같아서, 디스크 하나가 사라져도 나머지를 모두 XOR하면 사라진 값이 그대로 나옵니다. 아래에서 디스크 하나를 고장 내 보세요.

한계: 패리티 하나로는 한 번에 한 디스크만 복구할 수 있습니다. 두 개가 동시에 사라지면 식 하나로 미지수 두 개를 풀 수 없기 때문입니다. 그래서 RAID 6은 계산 방식이 다른 두 번째 패리티(Q, 리드-솔로몬 방식)를 더해 식을 두 개로 만듭니다.

5. RAID 레벨이 늘어난 배경

레벨 번호는 등급이 아니라 1987년 논문이 방식을 분류하려고 붙인 번호입니다. 논문은 1~5를 정의했고, 각 레벨은 앞 방식의 한계를 해결하는 흐름이었습니다. 0과 6은 나중에 붙었고, 10 · 50 · 60은 레벨을 겹쳐 쓴 조합입니다.

질문답
왜 2 · 3 · 4는 사라졌나RAID 2는 디스크 자체에 오류 정정(ECC)이 들어가면서 의미가 없어졌습니다. RAID 3은 모든 디스크가 함께 움직여 한 번에 요청 하나만 처리합니다. RAID 4는 쓰기마다 패리티 디스크 한 대에 몰려 병목이 생겼습니다. 패리티를 모든 디스크에 돌려 쓰는 RAID 5가 이 문제를 해결하면서 대체했습니다.
왜 5에서 6으로 갔나디스크가 수 TB로 커지면서 고장 난 디스크를 재구축하는 데 하루 이상 걸리게 됐습니다. 그동안 남은 디스크가 하나 더 고장 나거나, 읽을 수 없는 섹터(URE)를 만나면 RAID 5는 전체를 잃습니다. 일반 디스크의 URE 사양은 대략 12TB를 읽을 때 1번 수준이라, 대용량 RAID 5 재구축은 위험한 도박이 됐습니다.
0은 왜 0인가논문의 분류에는 없었고, 중복 없이 나눠 쓰기만 하는 방식이라 "중복 0"이라는 뜻으로 나중에 붙었습니다.
그다음은ZFS RAID-Z(2005)처럼 파일시스템이 직접 패리티를 관리하거나, 클라우드는 서버 여러 대에 조각을 흩어 저장하는 이레이저 코딩으로 확장했습니다.

6. 실무에서 꼭 알아야 할 것

포인트내용
RAID ≠ 백업실수로 지운 파일, 랜섬웨어, 잘못된 업데이트는 모든 디스크에 똑같이 반영됩니다. RAID는 "디스크 고장"만 막습니다. 백업은 따로 해야 합니다.
하드웨어 RAID서버의 RAID 컨트롤러(Dell PERC, HPE Smart Array 등)가 처리. OS에는 디스크 하나로 보입니다. 배터리 · 플래시 캐시로 쓰기를 보호합니다.
소프트웨어 RAID리눅스 md(mdadm)처럼 OS가 처리. 컨트롤러 없이도 되고 장비를 바꿔도 디스크를 그대로 옮길 수 있습니다.
write hole데이터와 패리티를 쓰는 도중 정전되면 둘이 어긋나는 문제. 배터리 캐시, 저널, ZFS 같은 구조로 막습니다.
디스크 선택SMR HDD는 재구축이 매우 느려 RAID에 부적합. 같은 시기 같은 모델 디스크는 비슷한 때 고장 나기 쉬우니, 고장 1대를 갈았으면 남은 디스크도 점검합니다.
cat /proc/mdstat                     # 소프트웨어 RAID 상태 · 재구축 진행률
sudo mdadm --detail /dev/md0         # 레벨 · 디스크 상태 · 고장 여부
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc   # RAID 1 만들기 (실습용 디스크로만)
sudo mdadm /dev/md0 --fail /dev/sdb --remove /dev/sdb    # 고장 처리 후 제거
sudo mdadm /dev/md0 --add /dev/sdd   # 새 디스크 추가 → 자동 재구축
lsblk -o NAME,TYPE,SIZE,MOUNTPOINT   # md 장치와 디스크 관계 확인

7. 용어 정리

용어뜻
RAID 레벨디스크를 묶는 방식을 구분하는 분류 번호. 숫자가 크다고 더 좋은 것은 아님
SLEDSingle Large Expensive Disk. RAID 이전 메인프레임의 대형 디스크
스트라이핑데이터를 일정 크기(스트라이프)로 잘라 여러 디스크에 나눠 쓰기. 동시에 읽고 써서 빠름
미러링같은 데이터를 두 디스크에 똑같이 쓰기
패리티XOR로 만든 검산 값. 사라진 데이터를 계산으로 되살림
XOR두 비트가 다르면 1, 같으면 0. A ⊕ B ⊕ B = A 성질로 복구 가능
리드-솔로몬RAID 6의 두 번째 패리티(Q)에 쓰는 오류 정정 수학. CD · QR 코드에도 사용
재구축(리빌드)새 디스크에 고장 난 디스크의 내용을 계산해서 다시 채우는 작업
핫 스페어미리 꽂아 둔 예비 디스크. 고장 시 자동으로 재구축 시작
디그레이드디스크가 고장 나 중복 없이 버티는 상태. 이때 하나 더 고장 나면 손실
MTTFMean Time To Failure. 고장까지의 평균 시간
UREUnrecoverable Read Error. 디스크가 읽지 못하는 섹터. 재구축 실패의 주된 원인
write hole데이터와 패리티 쓰기 사이에 정전되어 둘이 어긋나는 문제
이레이저 코딩데이터를 조각과 패리티로 나눠 여러 서버에 흩어 저장. 클라우드 스토리지 방식
