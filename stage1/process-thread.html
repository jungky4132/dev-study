프로세스와 스레드 한 장 그림

실행 중인 프로그램(프로세스)이 메모리를 어떻게 나눠 쓰고 운영체제가 어떻게 관리하는지, 프로세스가 어떤 상태를 오가고 어떻게 태어나는지(fork · exec), 한 프로세스 안에서 일을 나누는 스레드는 무엇을 함께 쓰는지 · STAGE 1 운영체제

핵심 정리

  • 프로세스 = 메모리에 올라가 실행 중인 프로그램 (코드 · 데이터 · 힙 · 스택). 코드 · 데이터는 크기가 고정된 정적 할당 영역, 힙 · 스택은 실행 중 크기가 변하는 동적 할당 영역
  • 운영체제는 PCB로 프로세스의 상태와 PC · 레지스터 값을 관리하고, 타이머 인터럽트가 오면 문맥 교환으로 다음 프로세스에 CPU를 넘긴다
  • 프로세스는 생성 → 준비 ⇄ 실행 → 종료를 오가고, 입출력을 기다리면 대기했다가 준비로 돌아간다
  • 프로세스는 부모가 fork로 자기를 복제하고, 자식이 exec로 새 프로그램이 되어 태어난다. 모든 프로세스의 조상은 PID 1(systemd)
  • 스레드는 프로세스 안의 실행 흐름: PC · 레지스터 · 스택은 따로, 코드 · 데이터 · 힙은 공유. 프로세스에는 최소 1개(메인 스레드)가 있다
  • 프로세스끼리는 메모리 독립(IPC로 통신), 스레드끼리는 메모리 공유(동기화 필요)

비유로 기억하기

  • 프로세스 = 방, 스레드 = 그 방의 일꾼(룸메이트). 방에는 일꾼이 최소 1명 있어야 일이 진행된다
  • 룸메이트는 방의 공용 물건(코드 · 데이터 · 힙 · 열린 파일)을 같이 쓰고, 자기 메모장(스택)과 책갈피(PC · 레지스터)는 따로 가진다
  • 냉장고를 동시에 열어 우유 개수가 꼬이는 것 = 경쟁 상태(문제), 한 명씩만 들어가는 화장실과 문 잠금 = 임계 구역과 뮤텍스(해결) · 섹션 13 동기화로 이어짐
  • 다른 방의 물건은 직접 못 쓰고 파이프 · 소켓 같은 통로(IPC)로 주고받는다
